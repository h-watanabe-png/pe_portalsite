## ⚠️ 重要な注意事項

GASのデプロイには**デプロイバージョンの数に制限**があり、過去のバージョンを削除すると現在のデプロイに影響が出る可能性があります。

### 実際の経験から

- 100回以上デプロイした後に、過去のバージョンを削除したら現在のバージョンに影響が出た
- デプロイバージョンの管理には注意が必要

---

## 📋 GASデプロイの制限と注意点

### 1. デプロイバージョンの制限

GASのデプロイには以下の制限があります：

- **デプロイバージョンの数**: 制限あり（正確な数は公式ドキュメントで確認が必要）
- **過去のバージョンの削除**: 現在のデプロイに影響する可能性がある
- **デプロイ履歴**: 一定数以上は保持できない可能性

### 2. 推奨される運用方法

#### 方法1: バージョン管理を最小限に（推奨）

**「新しいデプロイ」ではなく「バージョンを管理」を使用しない**

- 毎回「新しいデプロイ」を作成するのではなく、既存のデプロイを更新する
- これにより、デプロイバージョンの数が増えすぎることを防げる

**手順**:
1. 最初のデプロイ: 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で作成
2. 以降のデプロイ: 「デプロイ」→「デプロイを管理」→ 既存のデプロイを選択 → 「編集」→ 「新しいバージョン」で更新

#### 方法2: 定期的なクリーンアップ（注意が必要）

過去のバージョンを削除する場合は、**現在使用中のデプロイは削除しない**ように注意する。

**手順**:
1. 現在使用中のデプロイを確認
2. 古いバージョンのみを削除（現在のデプロイは残す）
3. 削除後、現在のデプロイが正常に動作するか確認

## 🔄 安全なデプロイフロー

### 推奨フロー: 既存デプロイの更新

```bash
# 1. ファイルを編集
# gas/フォルダ内のファイルを編集

# 2. clasp pushでGASに反映
python scripts\deploy_gas.py --force

# 3. GASエディタで既存のデプロイを更新
# 「デプロイ」→「デプロイを管理」→ 既存のデプロイを選択 → 「編集」→ 「新しいバージョン」で更新
```

**メリット**:
- ✅ デプロイバージョンの数が増えすぎない
- ✅ 過去のバージョンを削除する必要がない
- ✅ 現在のデプロイに影響が出にくい

### 注意が必要なフロー: 新しいデプロイを作成

```bash
# 1. ファイルを編集
# gas/フォルダ内のファイルを編集

# 2. clasp pushでGASに反映
python scripts\deploy_gas.py --force

# 3. GASエディタで新しいデプロイを作成
# 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で作成
```

**注意点**:
- ⚠️ デプロイバージョンの数が増える
- ⚠️ 定期的にクリーンアップが必要
- ⚠️ 過去のバージョンを削除する際は注意が必要

## 🔍 トラブルシューティング

### 過去のバージョンを削除したら現在のデプロイに影響が出た場合

1. **現在のデプロイを確認**
   - GASエディタで「デプロイ」→「デプロイを管理」を確認
   - 現在使用中のデプロイが存在するか確認

2. **新しいデプロイを作成**
   - 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で再作成
   - 新しいURLを取得

3. **コードを再デプロイ**
   - `python scripts\deploy_gas.py --force` でコードを反映
   - 新しいデプロイで動作確認

## 📊 デプロイ回数とバージョン管理

### デプロイ回数について

- **コードのプッシュ（clasp push）**: 制限なし、何度でも可能
- **デプロイバージョンの作成**: 制限あり、管理が必要

### 推奨される運用

1. **開発中**: clasp pushを頻繁に実行（問題なし）
2. **デプロイ**: 既存のデプロイを更新（バージョン数を抑える）
3. **クリーンアップ**: 定期的に不要なデプロイを削除（注意深く）
