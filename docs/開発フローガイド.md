## 📋 開発フローの選択

GASのデプロイ回数に制限はないため、**直接デプロイしてWeb Appで動作確認する方法**を推奨します。

### 推奨フロー: 直接デプロイ → Webで確認

**メリット**:
- ✅ シンプルで分かりやすい
- ✅ 実際の環境で動作確認できる
- ✅ デプロイ回数に制限がない
- ✅ ローカル環境のセットアップが不要

**手順**:
1. `gas/`フォルダ内のファイルを編集
2. `python scripts\deploy_gas.py --force` でデプロイ
3. Web AppのURLで動作確認
4. 必要に応じて修正して再デプロイ

---

## 🚀 基本的な開発フロー

### ステップ1: ファイルを編集

```bash
# gas/フォルダ内のファイルを編集
# - HTML: gas/index.html, gas/system-team-request.html など
# - CSS: gas/common.css
# - JavaScript: gas/dashboard.js, gas/form-handler.js など
# - GAS: gas/Main.gs, gas/Auth.gs など
```

### ステップ2: コードをプッシュ

```bash
# プロジェクトルートで実行
python scripts\deploy_gas.py --force
```

これでコードがGASプロジェクトに反映されます。

### ステップ3: デプロイ管理

```bash
# 既存のデプロイを更新（推奨）
python scripts\deploy_manage.py update

# または、新しいデプロイを作成
python scripts\deploy_manage.py create
```

**注意**: `deploy_manage.py`はコードのプッシュとデプロイ管理の案内を自動化します。
GASエディタでデプロイを更新または作成する手順が表示されます。

### ステップ4: Web Appで動作確認

1. **デプロイ管理スクリプトの案内に従う**
   - `deploy_manage.py`を実行すると、GASエディタが自動的に開きます
   - 表示された手順に従ってデプロイを更新または作成

2. **ブラウザでアクセスして動作確認**
   - デプロイ後に取得したURLにアクセス
   - 各機能をテスト
   - エラーがあれば修正して再デプロイ

## 🛠️ 便利なコマンド

### デプロイコマンド

```bash
# 通常のデプロイ（確認プロンプトあり）
python scripts\deploy_gas.py

# 強制デプロイ（確認プロンプトなし、推奨）
python scripts\deploy_gas.py --force
```

### claspコマンド（直接使用）

```bash
cd gas

# GASプロジェクトにプッシュ
clasp push --force

# GASエディタを開く
clasp open

# Web AppのURLを取得
clasp open --webapp

# ログを確認
clasp logs
```

## 📝 デプロイスクリプトの詳細

`scripts/deploy_gas.py`は以下の処理を自動化します：

1. claspのインストール確認
2. 設定ファイル（.clasp.json）の確認
3. clasp pushの実行（--forceオプション対応）
4. Web AppのURL取得（オプション）

**エラーが発生した場合**:
- claspがインストールされていない → `npm install -g @google/clasp`
- claspにログインしていない → `cd gas && clasp login`
- その他のエラー → エラーメッセージを確認

## 🎯 開発時のベストプラクティス

### 1. 小さな変更を頻繁にデプロイ

大きな変更を一度にデプロイするよりも、小さな変更を頻繁にデプロイして動作確認する方が効率的です。

### 2. デプロイ前にコードレビュー

デプロイ前に、変更内容を確認してからデプロイすることを推奨します。

### 3. エラーログの確認

動作確認時にエラーが発生した場合、GASエディタの「実行」→「ログを表示」でエラーログを確認できます。

### 4. バージョン管理

Gitでコミット・プッシュして、変更履歴を記録しておくことを推奨します。

```bash
# デプロイ後にGitにコミット
python scripts\git_commit_push.py "[自動] 機能追加: XXX"
```

## 🔍 トラブルシューティング

### clasp pushが失敗する場合

```bash
# clasp loginを再実行
cd gas
clasp login

# 強制プッシュを試す
clasp push --force
```

### Web Appが動作しない場合

1. **GASエディタでエラーを確認**
   - 「実行」→「ログを表示」でエラーログを確認
   - エラーがあれば修正して再デプロイ

2. **認証・認可の確認**
   - 会社ドメイン（@tomonokai-corp.com）でログインしているか確認
   - ホワイトリストに登録されているか確認

3. **デプロイ設定の確認**
   - Web Appのデプロイ設定を確認
   - 実行ユーザーとアクセス権限を確認

## 📊 デプロイ回数とバージョン管理について

### コードのプッシュ（clasp push）

**clasp pushの回数に制限はありません**。

- ✅ 何度でもプッシュ可能
- ✅ プッシュ回数による課金もなし
- ✅ 頻繁なプッシュで問題なし

### デプロイバージョンの管理

**デプロイバージョンの数には制限があり、過去のバージョンを削除すると現在のデプロイに影響が出る可能性があります**。

- ⚠️ デプロイバージョンの数に制限あり
- ⚠️ 過去のバージョンを削除する際は注意が必要
- ✅ 既存のデプロイを更新する方法を推奨

詳細は `docs/GASデプロイバージョン管理ガイド.md` を参照してください。

### 推奨される運用

1. **開発中**: clasp pushを頻繁に実行（問題なし）
2. **デプロイ**: 既存のデプロイを更新（バージョン数を抑える）
3. **クリーンアップ**: 定期的に不要なデプロイを削除（注意深く）
