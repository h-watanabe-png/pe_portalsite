     - ダッシュボード_集計

3. **連携用スプレッドシート（用途別）**

**用途**:
- NotebookLMでの検索・分析

## 🔗 連携設計

### 1. NotebookLM連携

#### データ構造の最適化

**NotebookLMが検索しやすい形式**:
- 構造化されたデータ（表形式）
- 自然言語での説明を含む
- タグやカテゴリで分類
- 関連情報をリンク

**実装方法**:
1. **スプレッドシートの公開設定**
   - 問い合わせ対応履歴シートをCSV形式で公開
   - NotebookLMが読み込める形式で提供

2. **データの構造化**
   - 各レコードに自然言語での説明を含める
   - タグやカテゴリで分類
   - 関連情報をURLやIDでリンク

3. **定期更新**
   - バッチ処理で定期的にデータを更新
   - NotebookLMが最新データを参照できるようにする

#### データエクスポート関数

```javascript
/**
 * NotebookLM用のデータをエクスポート
 * @return {Array<Object>} NotebookLM用の構造化データ
 */
function exportForNotebookLM() {
  const spreadsheetId = '1mivDNOXpZsE7oW7gF10Rq3NvnYjxjfiVQWp4LHIorL0';
  const sheet = SpreadsheetApp.openById(spreadsheetId)
    .getSheetByName('問い合わせ対応履歴');
  
  const data = getSheetDataOptimized(sheet);
  const headers = data[0];
  const rows = data.slice(1);
  
  // NotebookLM用に構造化
  return rows.map(row => {
    const record = {};
    headers.forEach((header, index) => {
      record[header] = row[index];
    });
    
    // 自然言語での説明を追加
    record.description = 
      `${record.対応日時}に${record.対応者}が対応。` +
      `内容: ${record.対応内容}。` +
      `結果: ${record.対応結果}。`;
    
    return record;
  });
}
```

### 2. Slack連携

#### スレッド管理の強化

**現在の設計**:
- 依頼_統合管理シートにSlackChannelId、SlackThreadUrl、SlackThreadTsを保存

**拡張設計**:
- 問い合わせ対応履歴シートにもSlack情報を保存
- 対応ごとにSlackスレッドをリンク
- スレッドの検索が容易に

#### Slack通知の強化

```javascript
/**
 * Slack通知を送信（拡張版）
 * @param {Object} data - 通知データ
 * @param {string} type - 通知タイプ
 * @return {Object} 送信結果
 */
function sendSlackNotificationEnhanced(data, type) {
  const config = getConfig();
  const webhookUrl = config.slack.webhookUrl;
  
  // 通知メッセージを構築
  const message = buildSlackMessage(data, type);
  
  // Slackに送信
  const response = UrlFetchApp.fetch(webhookUrl, {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify(message)
  });
  
  // スレッド情報を保存
  if (response.getResponseCode() === 200) {
    const responseData = JSON.parse(response.getContentText());
    saveSlackThreadInfo(data.requestId, responseData.ts, responseData.channel);
  }
  
  return response;
}
```

## 🔄 データフロー設計

### 問い合わせ対応フロー

```
1. 依頼受付
   ↓
2. 依頼_統合管理シートに記録
   ↓
3. Slack通知送信
   ↓
4. 対応開始
   ↓
5. 問い合わせ対応履歴シートに記録
   ↓
6. Slackスレッドにリンク
   ↓
7. 対応完了
   ↓
8. ナレッジベースに追加（必要に応じて）
   ↓
9. NotebookLMが最新データを参照
```

### データ更新フロー

```
1. 非エンジニアがスプレッドシートを直接編集
   ↓
2. GASトリガーが変更を検知（オプション）
   ↓
3. データの整合性チェック
   ↓
4. 関連データの自動更新
   ↓
5. Slack通知（必要に応じて）
```
